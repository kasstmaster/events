# Contacts, shared events and host administrator release

This application change remains entirely in `kasstmaster/events`, based on the reviewed `feat/household-subdomains` application tree. `main` is the operations branch and must not replace the application tree. The owner authorized PR creation, merge after checks and events-only deployment. Dropbox work was canceled and is excluded.

## Resulting behavior

- Contacts shows the existing four-digit address Guest ID beside the address title. Person IDs and all existing identities, responses and codes remain intact. Unmatched inline address input has a red Not found state and Create new address button. Street / PO Box, City, State and Zip Code support conservative prefilling/browser autofill and atomic guest/address saves. List/contact name buttons have equal padding.
- Optional AnyList sync is a capability of the operator-selected existing host household, using the shared contact model. It reads the selected source through an isolated manual GitHub job and a patched read-only protobuf adapter. Imports are atomic, version-checked, idempotent and nondeleting; ambiguous matches and address/parent moves are skipped rather than merged/duplicated. Nothing writes to Gatherings or its private state. [Secure setup](meyer-anylist.md) is required; deploying code alone does not connect AnyList.
- Routine connected/updated/saving/saved synchronization banners and the household-name “invites you” line are removed. Actionable failures/conflicts remain.
- Hosts no longer select SMS consent in the contact form. The signed-in adult's explicit successful RSVP records phone-scoped enrollment and one event confirmation with STOP instructions. Other skipped adults/children are not enrolled by that answer. The existing provider remains disabled; disabled submissions never become a later backlog, STOP is retained and uncertain attempts are not retried.
- Hosts and guests use the same event-body renderer. The host RSVP control is read-only. Host-owned values support double-click editing through the existing event editor; menu double-click and Table open the same editor. Template uses the common invitation/card editor. Private table templates use versioned scoped records and append fresh menu items on application, preserving existing claims. Interface wording/positions remain administrator-only. Editing toolbars are opaque in the selected container color, without changing ordinary container opacity.
- Existing host accounts can receive a separate platform administrator capability, keeping normal pages and bottom navigation. Their Home top toolbar alone adds Approvals, Hosts, Defaults and Templates. There is no household-specific build or hardcoded account/email in the shared code. Both normal host and administrator previews are read-only; host preview is limited to its household. Guest Home shares event cards with upcoming dates nearest first, then undated and recent past events.

## Live account handoff

Source/test changes do not promote a live account. An authenticated existing administrator is required:

1. On Hosts, select **Make administrator** for the exact owner-confirmed existing Meyer host email. Confirm that email and the current administrator password in the application, never chat.
2. Sign out and sign in freshly to the Meyer host. Verify the normal household/events and Home top tools: Approvals, Hosts, Defaults and Templates. Verify they are absent from its event toolbar and that host bottom navigation is intact.
3. Only after that succeeds, open its Hosts screen and **Remove old administrator**. Confirm the exact old administrator email and the current Meyer host password, then the destructive confirmation. The server requires the verified post-promotion login, removes only that legacy admin login/sessions and permanently closes setup. It does not delete a household, change ownership/passwords or run host account cleanup.

Do not remove the old live administrator using a fixture, setup reset, deployment shortcut or guessed identity. If an authenticated app session is unavailable, report this handoff as pending rather than claiming it occurred.
