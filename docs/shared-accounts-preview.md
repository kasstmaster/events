# Shared accounts and invitation editing — implementation preview

This branch is not approved for merge or deployment. Existing production behavior is unchanged. All verification uses synthetic isolated accounts and mocked providers.

The latest event changes use one address-household grouping helper for Address Book, manual RSVP selection and dashboards. Adults precede children, retaining authoritative creation order. Child surnames are omitted from the UI; existing saved surnames remain stored. White editing fields use dark text; event and card text retain deliberate leading spaces. Saved content continues to use page appearance. Event Settings and Create use an Invite guests transition to Address Book selection, preserving the actual unsaved form and uploaded files. The event bottom toolbar places Invite after Home. Your Plans precedes event content. RSVP dashboards display adult and child counts above each of the four category labels and place each RSVP action at the right.

Cards & Templates, previews and editors use dedicated pages. Export, print, share and email actions belong to the preview; editor Save and Close belong to its top toolbar. Card and appearance editors share the three-level toolbar renderer. Existing card documents and template overrides remain independent.

Additive platform records hold a private person account and a self-managed household profile. Initial family population happens once after an existing address credential is proven. An inviter cannot later overwrite that profile. Selected recipients are the conservative sharing default. Mailing address takes precedence over physical address, and private host notes never propagate. Shared identities, address codes, old records, responses and invitation ownership remain intact. Private usernames and recovery phones must never enter host contact projections. Registered accounts stop accepting full-name sign-in. Optional verified guest credentials at host registration attach the existing identity in the registration transaction.

Username recovery and e-vite delivery use the existing disabled-by-default SMS provider. No code enables SMS or changes credentials. Username recovery requires a verified recovery phone and a YES reply; NO cancels. E-vites persist receipts before dispatch, deduplicate event/phone deliveries, and restrict later sends to recipients originally skipped for a missing phone. Accepted or unknown sends are never retried. Group text previews currently require general invitations without private recipient variables. Native share/email remains an explicit user action.

Host household names are read-only. A password-confirmed administrator can rename the display name or claim a different valid domain label. Existing labels stay explicit aliases, and new domains remain pending until normal ownership, inventory, proof and asset checks pass. No live domain or route changes were performed.

AnyList pulls now maintain separate local and remote field baselines. Gather edits win conflicting edits; unrelated remote edits and added people remain eligible. An unchanged remote conflict cannot overwrite Gather on a later identical pull. **AnyList outbound writes and full two-way convergence are not implemented yet**; the existing adapter is read-only. Do not expose an outbound-sync action until the scoped write adapter, reconciliation acknowledgements and integration tests are complete.

Remaining release work includes full account/contact integration coverage, complete browser-suite updates for the new sign-in and editor interactions, and outbound AnyList support. The branch must not be presented as production-ready while these are outstanding.
